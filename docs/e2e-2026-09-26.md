# End-to-end run of 0.2.3 and 0.2.4 on the sandbox, 2026-09-26

0.2.3 split the review, fix and triage workflows into an agent job with a read-only token and a publish job with no agent. Three review passes checked it, but none of it had run on GitHub. This run did that on the sandbox, `jsnkle/ai-native-sdlc-test`, with real triggers, and then ran the 0.2.4 closing-the-loop and spec workflows from branches. Everything below was observed unless it says otherwise.

## Setup

- **Anthropic key.** A workspace of its own (`ai-native-sdlc-sandbox`) with a monthly spend limit, a service account with the Developer role, and a key scoped to that workspace with a 30-day expiry. A throwaway workflow called the Messages API with the repository secret and printed only the status and the `anthropic-workspace-id` response header: 200, and the sandbox workspace's ID.
- **Workflows switched on for the run:** Claude review, Claude mention, Build, and closing-the-loop and Spec on intent merge for their own tests. All were switched off again afterwards.
- **Test PR:** [#17](https://github.com/jsnkle/ai-native-sdlc-test/pull/17), a salutation helper with two planted defects: an unknown claim id returns `Dear Customer,` instead of raising `KeyError`, and the claim id is logged. All comments were posted from the owner's account, which is what the workflows trust.

## Closing the loop, 0.2.4

The 0.2.4 files were pushed to a sandbox branch, `e2e/0.2.4-loop`, and the workflow was dispatched from it (`gh workflow run closing-the-loop --ref e2e/0.2.4-loop`), so nothing merged to the sandbox's main. The broken-build commits of tests 4 and 6, plus one more, put three failures in the last five `ci` runs: z = 3.727, tier 3.

Run 36241493722:

- **`loop` job** (read-only token, no stored credentials): detection read tier 3, and Claude diagnosed from the failed runs' logs and wrote `intent/ci-failure-rate-e2e-pr17-build-break/intent.md`. Its transcript says it left the file uncommitted, as asked. The log passed the credential scan and was kept as an artifact, with the intent staged under `proposal/`.
- **`propose` job** (no agent): the `LOOP_GH_TOKEN` check passed, detection from the branch read tier 3 again, and `ops/propose.sh` committed the file as `closing-the-loop` and opened [PR #18](https://github.com/jsnkle/ai-native-sdlc-test/pull/18). The PR's detection report is the propose job's own (12:20:19), not the loop job's (12:18:35). ci, Build and Claude review ran on the PR, which a PR opened with the default token would not trigger.
- **The intent was right.** It traced all three failures to PR #17's deliberate breaks, quoted the run ids and commit messages, said `main` is unaffected, and proposed closing PR #17 and adding `e2e/*` to `ignore_branches`. Its open questions include whether excluding by branch name could hide a real failure, which is the decision a human should make.

PR #18 also shows the 0.2.4 files, because its branch was cut from `e2e/0.2.4-loop`. Dispatched from main, only the intent would appear.

The pre-release review then changed the propose job: its checkout keeps no credentials, it installs only PyYAML, and the push credential is set just before `propose.sh`. The reviewed files were dispatched again from `e2e/0.2.4-loop-2` (run 36242714733): both jobs passed, and the push with the late credential opened [PR #20](https://github.com/jsnkle/ai-native-sdlc-test/pull/20), with the intent committed as `closing-the-loop`.

## The spec workflow, 0.2.4

`spec-on-intent-merge.yml` was split the same way before release, at the owner's request. It was tested like the loop: the new workflow and a new accepted intent (`intent/letters-salutation/intent.md`) on a sandbox branch as its tip commit, dispatched with `--ref`. The dispatch was accepted even though the sandbox's main copy has no `workflow_dispatch` trigger.

Run 36241970100:

- **`spec` job** (read-only token, no stored credentials): found the one new intent, Claude wrote `spec.md` (15 KB; it decided the intent's open question, a claim with no name gives `null`, and kept the claim-id and PII rules), and the job staged it as an artifact.
- **`publish` job** (no agent): the token check passed, the file passed the checks, and it was committed as the bot and opened as [PR #19](https://github.com/jsnkle/ai-native-sdlc-test/pull/19). ci ran on the PR.

Before that, the publish step's script was run locally against seven artifacts: two good specs, a spec for an intent that already has one, a spec with no intent, a symlink, an extra file, a key-shaped string and an empty artifact. Only the first was published.

## What changed because of this run

In 0.2.4:

- `claude-mention`, `closing-the-loop` and `spec-on-intent-merge` check `LOOP_GH_TOKEN` before using it, and fail with a message that names it (test 2).
- When the fix loop's publish job stops, it says so on the PR and links the run (test 5).
- The fix loop's replies and summary are written as they read after the push. The summary in test 2 said its commit was "not pushed".
- Build triage is asked for the three-line summary only (test 4).

The token check has run on GitHub in closing-the-loop and the spec workflow, and passed in both. The `claude-mention` and `triage-failed-build` changes have not: those workflows run on comment and pull request events, which always use the default branch's copy of a workflow, so they cannot be dispatched from a test branch the way closing-the-loop was. They will first run when a project copies 0.2.4 onto its main.
