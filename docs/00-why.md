# Why the process has to change

## Code is no longer the bottleneck

Teams now use agents like Claude Code to write code at a pace that would have been unthinkable a year ago. The process around the code has not moved at the same pace. The approval gates, reviews, handoffs, and policies are the same ones that existed when a human typed every line, and they are now what stalls the gains.

The software development lifecycle (SDLC) takes software from idea to production. Most organizations run some version of six stages: plan, design, build, test, deploy, maintain. Traditionally each stage is a discrete phase owned by a different role. Product managers write requirements, architects turn them into designs, engineers build, QA verifies, release teams ship, operations watches. Work moves between phases through documents, tickets, and sign-offs.

That process is heavy on purpose. It exists to force accountability and alignment during what used to be weeks or quarters of implementation. PRDs, estimation rituals, and security reviews all made sense when writing the code was the slowest and most expensive step. It no longer is. The controls also assume every step is performed by a human, which is no longer true either.

## Three things become true

When build collapses from weeks to hours and nothing else changes:

1. **The bottleneck moves to the stages on either side of build.** Plan, review, test, and deploy still run at human speed, so they now set the pace of the whole loop.
2. **The controls stop matching reality.** Reviewing every line by hand was sensible when a person wrote it. It cannot keep up once agents produce most of the diff. Either a review queue builds or code ships under-reviewed, and a regulated organization can accept neither.
3. **Governance gets more expensive, not less.** Exceptions still route through committees that meet weekly or monthly, and there are now many more of them.

Security is the clearest example. A security team is sized for human output. When agents multiply that output, the security checks have to keep pace with the agents or the checks become the thing that fails.

## What an AI-native SDLC is

An AI-native SDLC keeps the old control objectives and changes the enforcement. The linear flow becomes a loop, AI is embedded at every point, and handover between stages is automated: each stage ends by committing an artifact, and the next stage begins by reading it.

| Stage | Traditional | AI-native |
|---|---|---|
| **Plan** | Requirements gathered by committee, refined through workshops and sign-offs, written up by hand. | The originator brainstorms with Claude and the result is captured as `intent.md`: human readable, machine actionable, committed to git. |
| **Design** | Spec written by analysts, parsed by designers. | Requirements and design compressed into one session with an agent, guided by organizational standards encoded as skills, versioned in git as `spec.md`. |
| **Build** | Tests and code handwritten; documentation written afterwards. | Tests and code generated by the agent from an approved `plan.md`; institutional knowledge maintained as versioned `CLAUDE.md` files and skills. |
| **Test** | QA gates at stage boundaries. | Every session verifies its own work; continuous evals regression-test the agent's configuration. |
| **Deploy** | Humans review every line; governance happens in review cycles, often inconsistently. | Layers of agentic review with human review reserved for intent and risk. Governance is enforced as the agent acts, with hooks as approval gates. |
| **Maintain** | Humans watch production for bugs. | Agents monitor live deployments. A breached control band is diagnosed and written back into the loop as a new `intent.md`. |

Most organizations sit somewhere between the two columns, and different stages can move at different times. See [02-adoption-order.md](02-adoption-order.md).

## Humans stay accountable

The thread through the right-hand column is the committed artifact. Each stage writes one to version control and the next stage reads it. The chain of commits is the audit trail: who asked for what, what the agent produced, who approved it.

What changes for people is where their attention goes. Instead of starting each stage from scratch, a person reviews what the agent produced and flagged, at a gate. A product owner accepts or rejects an intent. A product owner signs off a spec. An engineer approves a plan before any code is written. A code owner approves a PR informed by the review findings. A release manager authorizes a production deploy. No agent passes any of those gates on its own. Every decision that needs judgment still belongs to a named human, and the artifact records that they made it.

The loop keeps running. Human judgement stays above it.
